# Выпуск сборок и самообновление

Плеер обновляется сам: на вкладке «Профиль» есть карточка «Обновление» — проверка,
скачивание, установка. Автоматической проверки нет намеренно: приложение живёт в машине
и должно молча играть, а не предлагать обновиться посреди дороги.

Схема повторяет ту, что уже работает в Vitz Dashboard.

## Как это устроено

Исходники остаются в приватном репозитории, публикуются только сборки — в отдельном
**публичном** репозитории релизов. Поэтому в APK нет и не должно быть никакого токена:
извлечь его из установочного файла элементарно.

Приложение ходит по постоянным ссылкам последнего релиза:

```
https://github.com/<владелец>/<репозиторий>/releases/latest/download/version.json
https://github.com/<владелец>/<репозиторий>/releases/latest/download/VitzMusic-release.apk
```

Такие ссылки не требуют обращения к API GitHub и не упираются в его лимиты для анонимных
запросов. Расплата — **имена файлов постоянные**: переименовать их нельзя, иначе установленные
копии перестанут находить обновление.

`version.json` — манифест версии:

```json
{
  "versionName": "0.1.15",
  "versionCode": 16,
  "sizeBytes": 17721768,
  "notes": "Что изменилось"
}
```

Решение об обновлении принимается по `versionCode`: он больше установленного — есть
обновление. `notes` показывается перед скачиванием.

Установка идёт через системный `PackageInstaller`, а не через «открыть файл»: он сообщает
результат, и по нему видно, что именно пошло не так — отказ пользователя, нехватка места,
несовпадение подписи.

## Какой репозиторий создать

| Что | Значение |
|---|---|
| Владелец | `Cracer00` |
| Имя | `VitzMusic-releases` |
| Видимость | **Public** |
| Описание | Сборки Vitz Music. Исходники — в приватном репозитории. |
| README | нужен: в пустом репозитории нельзя создать тег, и публикация обрывается |
| Файлы релиза | `VitzMusic-release.apk`, `version.json` |

Имя и владелец зашиты в двух местах и должны совпадать:

- [`android/src/main/java/com/vitz/music/app/update/UpdateRepository.kt`](../android/src/main/java/com/vitz/music/app/update/UpdateRepository.kt) — константы `OWNER` и `REPOSITORY`;
- [`scripts/release.ps1`](../scripts/release.ps1) — переменные `$RepoOwner` и `$RepoName`.

Создавать вручную не обязательно — скрипт выпуска сделает это сам при первом запуске
с ключом `-CreateRepo`, включая README (без первого коммита GitHub отвечает
«Repository is empty» и релиз не создаётся).

Вручную это выглядит так:

```bash
gh repo create Cracer00/VitzMusic-releases --public --description "Сборки Vitz Music. Исходники — в приватном репозитории."
```

В репозитории релизов не должно быть исходного кода — только README и сами релизы.

## Выпуск

Один раз на машине — вход в GitHub:

```bash
gh auth login
```

Дальше каждый выпуск:

```bash
powershell -File scripts/release.ps1 -Notes "Что изменилось"
```

Первый раз — с созданием репозитория:

```bash
powershell -File scripts/release.ps1 -Notes "Первый релиз" -CreateRepo
```

Что делает скрипт:

1. проверяет, что ключ подписи на месте;
2. собирает `:android:prepareReleaseArtifacts` — подписанный APK и `version.json` в `dist/release`;
3. сверяет подпись собранного APK (`CN=Vitz Music`) — отладочной подписью обновление поверх не встанет;
4. создаёт репозиторий и первый коммит, если их ещё нет;
5. публикует релиз с тегом `v<версия>` и обоими файлами.

Полезные ключи:

- `-DryRun` — собрать и всё проверить, ничего не публикуя;
- `-ReplaceExisting` — перевыложить релиз с той же версией (если прошлая попытка оборвалась);
- `-TagSource` — поставить тег на коммит исходников;
- `-GhPath` — путь к `gh.exe`, если его нет в PATH.

Версия поднимается сама: `versionName`/`versionCode` растут, когда изменился отпечаток
исходников. Повторная сборка без правок номер не двигает — поэтому и релиз с той же
версией скрипт откажется публиковать без `-ReplaceExisting`.

## Ключ подписи

Лежит в `keystore/vitz-music.jks`, пути и пароли — в `local.properties`. Оба открытым
текстом исключены из git.

Ключ обязан быть постоянным: Android ставит обновление поверх, только если новая сборка
подписана тем же ключом, что и установленная. **Потеря ключа означает, что обновлять уже
установленные копии больше нечем** — только удалять приложение и ставить заново, теряя
скачанную музыку и вход.

Если ключа на машине нет, сборка не падает: релиз подписывается отладочным ключом. Такой
APK ставится, но обновлением для подписанной сборки не станет — скрипт выпуска специально
это проверяет и останавливается.

### Бэкап ключа

В репозиторий едет зашифрованный архив `keystore/release-key.tar.gpg` — ключ и пароли
вместе. Порознь они бесполезны: ключ без паролей не открыть, пароли без ключа ничего не
подписывают, поэтому и бэкап имеет смысл только общий.

Открытым текстом в репозитории им не место, даже приватном. Дело не в чужих глазах, а в
том, что `actions/checkout` выкладывает рабочий каталог на раннер GitHub при каждом деплое,
а рядом в том же каталоге работают сторонние экшены. Шифрование делает эту разницу
неважной: даже утёкший репозиторий не даёт ничего без парольной фразы.

Создать или обновить бэкап (спросит парольную фразу — её место в менеджере паролей,
рядом с ключом она смысла не имеет):

```bash
tar -cf - keystore/vitz-music.jks local.properties | gpg --symmetric --cipher-algo AES256 --output keystore/release-key.tar.gpg
```

Восстановить на новой машине:

```bash
gpg --decrypt keystore/release-key.tar.gpg | tar -xf -
```

После восстановления поправьте в `local.properties` строку `sdk.dir` — путь к Android SDK
на каждой машине свой, а в архив он попадает вместе с остальным файлом.

Пересоздавайте архив при смене паролей подписи. Сам ключ не меняется никогда — в этом вся
его суть, — так что в остальное время файл лежит без изменений.

Проверить, что бэкап читается, не разворачивая его:

```bash
gpg --decrypt keystore/release-key.tar.gpg | tar -tf -
```

Правила `.gitignore` для этого каталога исключают его содержимое как `keystore/*`, а не
`keystore/`: из исключённого каталога git не может вернуть отдельный файл обратно — он в
такой каталог просто не заходит, и `!keystore/*.gpg` не сработал бы.

## Первая установка

Сборка с ключом — это другая подпись, чем у всего, что ставилось на магнитолу раньше.
Поставить её поверх не получится: система ответит «подпись не совпадает». Один раз нужно
удалить прежнее приложение и поставить новое — вход и скачанные файлы при этом теряются,
каталог восстановится сам из `/sync`. Дальше все обновления идут поверх, изнутри приложения.

Отладочная сборка (`com.vitz.music.app.debug`) живёт рядом и ничему не мешает: у неё другой
идентификатор приложения. Приборка ищет сначала релизную, потом отладочную.
